This report preserves the pre-publication engineering verification. Statements
about Git status and pending publication describe that earlier stage. The
subsequent authorized source release is recorded in [github-release.md](github-release.md).

tensors, executed on CPU and RTX 4060 Laptop CUDA, exported, reloaded and

## Full checkpoint storage and reconstruction

Dense master file: **1,188,291,675 bytes**. Packed file: **197,365,045 bytes**. Actual file-size ratio: **6.0207808x**. Frozen dense reconstruction also measured **1,188,291,675 bytes**. These are filesystem measurements, including serialization metadata, not theoretical bit-count estimates.

264,241,152 projection parameters are stored as ternary two-bit codes and FP32
per-tensor scales. Embedding/head and norms remain FP32. Per-tensor checksums,
container checksum, exact config/quantizer/architecture, shapes, offsets, code
validity, canonical padding and finite values are validated by the importer.
The source full-size quantizer device is CPU. Two independent seed-300 exports produced the same packed SHA-256: `c45716f5574bac9990dde484df232dee50a56101f015341750b0724380529192`. No second full model is needed
for export or comparison; verification releases each full model before loading
its reference. Disk preflight runs before large writes and files use exclusive
creation. Host and device guards precede decoding/allocation where applicable.

Against the corresponding CPU-quantized model: packed CPU maximum logit error
**0**, packed CUDA FP32 maximum error **2.0265579223632812e-6**. The CLI separately
freezes the reference on the export quantizer's device before comparison and
observed **0** for full packed-vs-reference CUDA logits. These are compatible
observations: one is cross-device floating-point error, the other compares
identical reconstructed weights on the same device. Full-size automated CPU
export/reload also passed bitwise logit equality.

Master QAT recomputed on CUDA differs from CPU by **0.00031979382038116455**
maximum logit error. Investigation in
`artifacts/release-full-final/quantizer-devices.json` found **2 differing ternary
codes among 264,241,152 eligible weights**, with a maximum scale difference of
**1.862645149230957e-9**. This explains why cross-device master-QAT comparison
needs separate tolerances from packed reconstruction. The benchmark does not
conceal this effect behind a claim of bitwise CPU/CUDA equivalence.

Full-file checksums, including dense files, are streamed into
`artifacts/release-summary-final/checksums.json`. Packed integrity is enforced by the
application; dense files have strict weights-only/schema/finite-state checks
and external release checksums, without an embedded cryptographic signature.
Dense files must be locally trusted. No unsafe weights_only=False fallback exists.

Full FP32 frozen dense and packed loading have the same measured allocated
forward peak: 1,360,005,632 bytes. Small FP32 variants also match at 14,703,616
bytes. Packed storage does not give proportional VRAM savings. Timing variation
and extremely short generation runs do not support a packed-kernel speedup
claim. QAT is slower than frozen reconstruction because it requantizes weights
every forward; freezing dense weights provides that benefit independently of
file storage. CUDA reserved peaks can differ due to caching history.

BF16 changes numerical results: maximum logit difference versus CPU FP32 is
0.01397252082824707 for the full frozen model and 0.03923320770263672 for the
trained small frozen model. Both file paths show the same precision error.
BF16 autocast did not reduce full-model peak allocation at context 8 because
FP32 weights stay resident and casts/workspaces add memory. The earlier
training optimization result (120.8 to 91.5 MiB) remains valid for its separate
training/batch/context conditions; it is not generalized to this inference run.

JSON and CSV rows include actual CPU working set, process-lifetime peak,
forward allocated/reserved peaks, distinct loading peaks, latency samples,
throughput, dtype, backend, model size, context, repeats and source artifact.
The evidence is in `artifacts/release-{full,demo}-storage/results.json` and
`artifacts/release-summary-final/benchmarks.{json,csv}`.

## Problems found and resolved

1. The initial full packed reload hit an overly conservative training-derived
   host budget after decoding. The loader now reads a bounded untrusted header
   only for preflight, checks config bounds, then runs full integrity validation
   and decode. Inference uses an explicit incremental budget; CUDA preflight
   distinguishes training from inference. A clean end-to-end run completed.
2. CPU/CUDA master-QAT tolerances initially conflated reduction changes with
   checkpoint reconstruction. The two differing codes were measured directly;
   packed comparisons now freeze the reference on its export device. Both the
   strict reconstruction result and the larger device effect are reported.
3. The first demo checkpoint stored PyTorch's TorchVersion string subclass in
   progress metadata, which the default weights-only unpickler rejected. New
   checkpoint metadata is normalized through JSON primitives. The original
   600-step training weights were preserved and explicitly finalized using a
   narrow allowlist for that known string subclass; no additional updates or
   arbitrary pickle fallback were used. A regression test covers both portable
   and legacy checkpoint metadata.

The interruption ledger is `artifacts/release-attempts.json`. Preliminary files were not deleted or overwritten. Successful final results
are clearly separated from interrupted attempts. New context-dependent CUDA
workspace checks also guard CLI forward/generation after loading weights.
