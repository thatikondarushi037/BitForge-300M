Completed 2026-11-04 using `.venv\Scripts\python.exe`: Python 3.13.7,
PyTorch 2.7.1+cu118, CUDA runtime 11.8, RTX 4060 Laptop GPU. No dependencies

## Tokenizer and corpus provenance

`ByteTokenizer` encodes exact UTF-8 bytes without normalization or automatic
special tokens. Its versioned metadata fixes this mapping:

| IDs | Meaning |
| --- | --- |
| 0 through 255 | Literal byte values |
| 256 | Reserved BOS |
| 257 | Reserved EOS |
| 258 | Reserved PAD |
| Vocabulary size | 259 |

Specials are not inserted or trained in this experiment. Decode skips them by
default and can reject them explicitly. Encoding/decoding valid Unicode text
round trips exactly. Arbitrary generated byte sequences need not be valid UTF-8;
strict decoding raises an error, while the generation CLI uses replacement
characters for invalid sequences. There is no learned vocabulary, compression,
word segmentation, chat format, document-boundary modeling, or padding support.
Perplexity is measured per byte token, not per word or subword token.

`data/dev_corpus.txt` is **original assistant-generated English prose**, created
locally for this milestone: 22 paragraphs about a fictional workshop. It is
offered under **CC0-1.0**, to the extent rights apply. No third-party passages
or datasets were downloaded. See `data/README.md` and the machine-readable
`data/dev_corpus.manifest.json`.

- Encoding: UTF-8 with LF newlines; all current characters are ASCII.
- Exact size: **5,807 bytes / 5,807 characters**.
- SHA-256: `9a37fcfa0fc55b65c7090240126bc83200379af993417d0eb8b198140c4864ce`.
- `.gitattributes` marks this corpus `-text` to preserve its hashed bytes.
- The loader verifies an adjacent manifest's byte count and SHA-256. An
  explicitly selected alternate local corpus has its actual hash recorded;
  it must be valid UTF-8 and appropriately licensed by its provider.

## Split isolation and batching

The loader decodes the corpus and selects the paragraph boundary nearest the
requested 80% training point. If no paragraph boundary exists, it splits at a
Unicode character boundary. It preserves every byte without stripping or
normalizing text. **Splitting happens before tokenization and window creation.**

For the measured corpus, the boundary is byte **4,751**:

| Split | Byte tokens | Evaluated next-token targets |
| --- | ---: | ---: |
| Training | 4,751 | 4,750 |
| Validation | 1,056 | 1,055 |

The actual validation share is about 18.18%, due to paragraph alignment. Split
hashes are also recorded in every run's metrics/checkpoint. The cross-boundary
transition from the last training byte to the first validation byte is excluded.
Training and validation remain topically similar parts of one tiny story;
split isolation prevents window leakage, not shared phrases or topics.

`NextTokenBatcher` samples uniformly with replacement from valid start indices
in a single split, using its own seeded CPU `torch.Generator`. Each window has
`sequence_length + 1` tokens; inputs omit its last token and labels omit its
first. Overlapping windows are allowed inside training only. The private RNG
state is checkpointed, so resumption selects the same next batch.

Evaluation is exhaustive and deterministic. Fixed-length chunks cover each
adjacent-token target once, followed by any shorter tail. Neighboring chunks
share the one byte needed to form the next shifted input/target pair, but no
target is counted twice. Context and absolute positions restart in each chunk.
Cross-entropy uses `reduction='sum'` for each batch; these sums are accumulated
and divided by the **total number of target tokens**, including the short tail.
Perplexity is `exp(total_negative_log_likelihood / total_target_tokens)`.

## Model and training configuration

The unchanged decoder uses tied full-precision token embeddings/output weights,
sinusoidal positions, two pre-RMSNorm blocks, four attention heads, width 64,
and a GELU FFN of width 128. Attention/FFN projections reuse the original
BitLinear. Vocabulary is 259 and maximum context is 64 for text experiments.
The resulting model has **82,432 unique trainable parameters**.

The measured run uses FP32, sequence length 64, batch size 16, seed 42, and
300 AdamW steps. Learning rate is 0.003, weight decay is 0.01, and gradients
are clipped at norm 1.0. It checks finite losses/gradient norms, enables
deterministic algorithms, configures cuBLAS before importing torch, disables
TF32 matrix multiplication, and seeds Python and PyTorch. No CPU fallback is
implicit. The CLI exposes architecture, batch, context, seed, learning-rate,
corpus, validation-fraction, device, and total-step settings.

The text pipeline rejects configurations above 2M parameters or context 256
before constructing a model. Batch size is bounded at 64 and steps at 10,000.
These guardrails are not a general GPU memory estimator; use the measured
defaults for the 8 GB GPU. Output directories must be new, and checkpoints are
created exclusively. Existing experiments are never overwritten.

## Checkpoint restoration and generation

The version-1 checkpoint contains model state, AdamW state, architecture
configuration, tokenizer metadata, completed optimizer step, corpus hash and
split metadata, training settings, batch-generator state, and CPU/CUDA torch
RNG states. Python's RNG is seeded but unused after initialization; there is
no stochastic Python operation to resume. Checkpoints are saved at the end
of a run, not periodically or on interruption.

Loading explicitly uses `torch.load(..., map_location='cpu', weights_only=True)`.
The loader validates the format, exact tokenizer mapping, and small model
configuration before model construction. There is **no unsafe pickle fallback**.
Only load locally produced checkpoints: restricted loading does not guarantee
protection against malformed tensors, resource exhaustion, or all file risks.
No remote checkpoint or dataset loading exists in these scripts.

The primary checkpoint restored step **300**, batch RNG state, and **bitwise
identical logits**. CPU and CUDA tests additionally demonstrate that the next
optimizer update after restoration matches uninterrupted training exactly,
including loss, every model parameter, AdamW step counters, and moment tensors.

An actual CLI resume was also run to total step **310**, in the separate
`artifacts/milestone-3-text-resumed/` directory. Its initial full-training and
validation losses exactly matched the primary run's final losses. After ten
additional steps, training loss was 2.9789802792 and validation loss was
2.9823387110 (perplexity 19.7339146417). The timed phase took 0.5910857 seconds;
the restored step was 310. This is a continuation check, not a tuned replacement
for the reported 300-step experiment. Resume rejects changed training settings
or a corpus/split hash mismatch; `--steps` always means the desired **total**.

Greedy generation supports one nonempty prompt. It repeatedly evaluates the
last context-length tokens, selects the maximum-logit byte, and appends it.
It masks the untrained special IDs. There is no sampling or KV cache; rolling
contexts reset sinusoidal position zero. Generation stops at the requested
byte count, not EOS. The returned tensor includes both prompt and new tokens.
