# Reproducing the release

Run from the repository root in the prepared environment described in
[windows-setup.md](windows-setup.md). Inference and experiments have no network
dependency. Output directories must be new; do not reuse the recorded paths.

## Tests

```powershell
python -m unittest discover -s tests -v
python -m unittest discover -s tests/expensive -v
python scripts/run_release_tests.py --include-full --output artifacts/reproduction-tests.json
```

The last command runs both suites and records actual pass/fail/skip counts and
the complete test log. Full-model tests are excluded from ordinary discovery;
exclusion is not reported as a passing or skipped test. CUDA-only tests are
explicitly skipped on hosts without CUDA.

## Original paired research comparison

```powershell
python scripts/prepare_engineering_corpus.py
python experiments/phase1_advanced.py --output-dir artifacts/reproduction-qat --steps 100
python experiments/benchmark_advanced_loading.py artifacts/reproduction-qat
```

The corpus is deterministic, original CC0 procedural text, generated offline
with seed 606. Its byte-level SHA-256 is
`e9d99fa6fe88b266989f61793b3bedd1c61a8dd398b5cb45ac2df1a58f1a6942`.
Splitting occurs at a paragraph boundary before windows are sampled. The
manifest and results record both split hashes. Repeated templates across the
split limit the validity of language-quality conclusions.

## Trained experimental demo

```powershell
python experiments/release_demo.py --output-dir artifacts/reproduction-demo --steps 600
python -m bitforge demo --checkpoint artifacts/reproduction-demo/demo.bft --device cuda --prompt "The technician will " --max-new-tokens 32
python -m bitforge verify-checkpoint --checkpoint artifacts/reproduction-demo/demo.bft --reference artifacts/reproduction-demo/demo.pt --device cuda
python experiments/benchmark_release_storage.py --packed artifacts/reproduction-demo/demo.bft --output-dir artifacts/reproduction-demo-storage --sequence-length 64 --generation-tokens 16 --training-status "600 updates, offline CC0 synthetic corpus, seed 42"
```

Seed 42, 600 AdamW updates, FP32, LR 0.001, weight decay 0.01, clipping 1,
batch 4, context 64; SDPA enabled, no activation checkpointing. The model has
1,378,176 parameters. `training.pt` retains optimizer and RNG states;
`demo.pt` is the portable inference checkpoint; `demo.bft` is the packed file.
Outputs are repetitive and demonstrate the pipeline, not general language skill.

The recorded run completed training in `artifacts/release-demo/`. A metadata
serialization bug was then repaired without more updates, producing
`artifacts/release-demo-final/`. The exact repair command used was:

```powershell
python experiments/release_demo.py --output-dir artifacts/release-demo-final --from-training artifacts/release-demo/training.pt
```

This explicit repair mode narrowly allowlists PyTorch's `TorchVersion` string
subclass for that locally generated checkpoint. The application never enables
arbitrary pickle loading. Normal new runs sanitize metadata into JSON primitives
and need no repair. Both preliminary and final artifacts were preserved.

## Full 297M model: execution and storage, no training

```powershell
$env:CUBLAS_WORKSPACE_CONFIG = ':4096:8'
python experiments/release_full_model.py --output-dir artifacts/reproduction-full --threads 4
python -m bitforge model-info --checkpoint artifacts/reproduction-full/full.bft
python -m bitforge verify-checkpoint --checkpoint artifacts/reproduction-full/full.bft --reference artifacts/reproduction-full/full-master.pt --device cuda
python -m bitforge demo --checkpoint artifacts/reproduction-full/full.bft --device cuda --prompt "The " --max-new-tokens 2
python experiments/benchmark_release_storage.py --packed artifacts/reproduction-full/full.bft --output-dir artifacts/reproduction-full-storage --sequence-length 8 --generation-tokens 2 --training-status "Random initialization, seed 300, zero updates"
```

Seed 300 initializes real FP32 weights. The runner verifies 297,059,328
parameters, CPU FP32 forward, CUDA FP32/BF16 forward, finite `[1,8,32000]`
logits, two generated byte tokens, packed export, and sequential CPU/CUDA
reloads. CUDA memory and disk-space preflight run before full allocation/writes.
The host guard uses available physical memory, not just total installed RAM.

The storage benchmark materializes a separate frozen dense checkpoint and
compares it to the identical packed reconstruction. FP32 tensors remain resident
even during BF16 autocast. It runs one model at a time, two warm-ups, five timed
forwards, batch 1, with synchronization. Generation has no KV cache. Load timing
includes validation and device transfer and is a single observation, not a
statistically repeated cold-cache benchmark. CPU RAM values are actual Windows
working set and process-lifetime peak, not resettable per-stage peaks.

The full target has a 32K output dimension but only a byte tokenizer is provided.
Generation restricts sampling to IDs 0..255 and prints an untrained-model notice
in `demo`. The remaining 32K IDs have no trained tokenizer mapping. Random
output is not evidence of language ability.

CPU/CUDA reduction order can change near-threshold QAT codes. Therefore the
full runner records master-model cross-device differences separately. The
packed reference fixes CPU-generated codes: its CPU logits reconstruct exactly
and its CUDA difference is measured at FP32 tolerance. BF16 differences are
reported separately and are not checkpoint corruption.

The recorded successful full run is `artifacts/release-full-final/results.json`.
Earlier `release-full/results.json` preserves a conservative host-preflight
failure; subsequent `release-full/verification.json` and the clean final run
verify the resolved behavior. No failed attempt was silently counted as success.

## CLI examples

```powershell
python -m bitforge generate --checkpoint artifacts/release-demo-final/demo.pt --device cpu --prompt "The technician will " --max-new-tokens 32 --verbose
python -m bitforge generate --checkpoint artifacts/release-demo-final/demo.bft --device cuda --prompt "The technician will " --temperature 0.8 --top-k 40 --top-p 0.9 --seed 42 --max-new-tokens 32
python -m bitforge benchmark --checkpoint artifacts/release-full-final/full.bft --device cuda --sequence-length 8 --warmup 2 --repeats 5 --generation-tokens 2
python -m bitforge verify-checkpoint --checkpoint artifacts/release-demo-final/demo.bft --device cpu
```

Temperature 0 selects greedy decoding. Positive temperature enables seeded
multinomial sampling after top-k and nucleus filtering. Maximum new tokens are
bounded to 512. BF16 is CUDA-only. Missing, corrupt, unsupported and incompatible
files produce an error and exit code 2. Legacy config-bearing training checkpoints
remain supported; raw state dictionaries without architecture metadata must
first be wrapped with their known configuration, never guessed.

Do not run other CUDA jobs concurrently with timing experiments. Reproducibility
applies to initialization and data/order in this pinned environment; latencies
vary with laptop power/thermal state and other workloads. No full pretraining,
native low-bit kernels, long-context full-model validation, or publication is
part of this release candidate.

## Repeated generation and quantizer-device investigation

After producing the reproduction files above:

```powershell
python experiments/benchmark_generation.py --full-packed artifacts/reproduction-full/full.bft --full-dense artifacts/reproduction-full-storage/dense-reconstructed.pt --demo-packed artifacts/reproduction-demo/demo.bft --demo-dense artifacts/reproduction-demo-storage/dense-reconstructed.pt --output artifacts/reproduction-generation.json --repeats 5
python experiments/inspect_quantizer_devices.py --checkpoint artifacts/reproduction-full/full-master.pt --output artifacts/reproduction-quantizer-devices.json
```

Generation uses one warm-up plus five observations per model/device/precision;
raw samples and generation-specific GPU peaks are recorded. It remains a tiny
2-token full-model smoke test or 16-token small-model measurement, with no KV
cache. The investigation compares codes/scales one projection at a time rather
than retaining two full models. The recorded full model had two differing codes
between CPU and CUDA reductions; this is separate from packed reconstruction.

To rebuild the review summary on the original local artifact layout, use a new
directory with `python scripts/summarize_release.py --output-dir artifacts/my-summary`.
It consumes the successful final runs and final test/CLI logs and streams binary
checksums; it requires the locally generated binaries. It does not synthesize
missing measurements.
